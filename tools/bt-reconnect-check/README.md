# Bluetooth のつなぎ直しの確認手順

ZMK や Zephyr の版を上げたとき、または `src/split_yield.c` に手を入れたときに、PC とのつなぎ直しで確立の失敗（切断理由 `0x3e`）が連発しないことを確かめる道具です。
経緯と判断は `docs/bluetooth-stability.md` にあります。

## 中身

- `module/`：計測の補助。接続と切断、通信条件の変化を右手側のメモリに記録し、USB のシリアルポートから読み出せるようにします。タイマーも無線への送信もフラッシュへの書き込みもしません。本番のファームには入れません。
- `port-of.sh`：右手側（または左手側）のコンソール用シリアルポートの名前を調べます。
- `min-cmd.sh`：ポートを開いて記録を読み、必要なら命令を1文字送ります。`d` は読み出し、`x` は PC との接続を1回切る、`b` はブートローダーへ入る、です。
- `min-parse.py`：読み出した記録から、最後の切断のあとに何回失敗して何ミリ秒で戻ったかを出します。
- `drop-series.sh`：切断と復帰の確認を指定回数くり返します。

## 手順

WSL 上で、Windows の PC に右手側を USB でつないだ状態で行います。左手側は電源を入れて、右手側とつながった状態にします。

1. 計測の補助を足した右手用ファームをビルドします。本番と同じコマンドに、モジュールを1つ足すだけです。

   ```sh
   west build -s zmk/app -d .build/R-check -b xiao_ble//zmk -p -S studio-rpc-usb-uart -- \
     -DZMK_CONFIG=<このリポジトリ>/config \
     "-DZMK_EXTRA_MODULES=<このリポジトリ>;<このリポジトリ>/tools/bt-reconnect-check/module" \
     -DSHIELD=coron_R
   ```

2. 右手側へ書き込みます。
3. PC と Bluetooth でつながったのを確かめてから、切断を 24 回以上くり返します。

   ```sh
   tools/bt-reconnect-check/drop-series.sh check 24
   ```

4. 出力の各行 `DROP check #N: failed=… back_ms=…` を見ます。

## 合否の目安

2026-10-05 の実測値です。PC は Realtek RTL8922AE、キーボード側は Zephyr `v4.1.0+zmk-fixes`（`10ba6d0c`）でした。

| 構成 | `failed` が 1 以上の回 | `back_ms` |
|---|---|---|
| `split_yield.c` あり | 94 回中 0 回 | 1000〜2500 |
| `split_yield.c` なし | 24 回中 4〜6 回（1回あたり 6〜37 回の失敗、30〜45 秒） | 失敗が無い回は 1000〜2500 |

`failed` が 1 以上の回が出たら、`split_yield.c` が効いていません。
左手側との接続が切れる（行末が `left=off` になる）場合は、Zephyr に接続パラメータ更新の修正（`b2aee46d`）が入っているかを確かめてください。

## 注意

- 終わったら、計測の補助を外した本番のファームへ書き戻します。右手側で `b` を送るとブートローダーに入れます（`min-cmd.sh /dev/null b`）。
- この PC で、シリアルポートの一覧を `Win32_SerialPort` で取ってはいけません。一覧の取得は全部の COM ポートに触るので、ペアリング済みのヘッドホンの Bluetooth シリアルポートにも触ることになり、Windows が 5 秒かけてそのヘッドホンへ接続を試みます。そのあいだ PC の Bluetooth が塞がり、つなぎ直しが 4〜17 秒に延びて見えます。`port-of.sh` はデバイスツリーを読むだけにしてあります。
- 切断をきっちり同じ間隔でくり返すと、PC 側の周期的な動作と同期して見かけの規則性が出ることがあります。傾向を調べるときは間隔を乱数でばらしてください。
- `port-of.sh` には、この個体の USB シリアル番号（右 `B17318CDBE9A61B1`、左 `743A486E04021F9D`）が書いてあります。別の個体で使うときは書き換えます。
