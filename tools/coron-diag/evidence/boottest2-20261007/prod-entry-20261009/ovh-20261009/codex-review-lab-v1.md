1. blocker — `local/coron-diag/src/diag_lab.c:264-269`: `lab_init()` puts four `crash_rec` objects on the 2 KB main stack. The linked frame is 13,496 bytes, while `.build/R-lab/zephyr/.config:270` sets `CONFIG_MAIN_STACK_SIZE=2048`; POST_KERNEL init runs on that thread at `zephyr/kernel/init.c:500-519`. This can fault before recording begins. Fix: preserve `crash_n/crash[]` in place and clear only the live prefix with `offsetof(struct labrec, crash_n)`; do not use a temporary array.

2. blocker — `local/coron-diag/src/diag_lab.c:279,296`: the printk hook is installed at POST_KERNEL priority 0, then UART replaces it at `zephyr/drivers/console/uart_console.c:591-624` priority 60. Consequently the assert text, including `Actual EVENT_OVERHEAD_START_US`, does not reach `pk[]`. Fix: split initialization; start TIMER4 early, but install the hook at APPLICATION priority 99. Save the previous hook and tee to it outside fatal/ISR capture so later printk users are not silently disconnected.

3. blocker — `local/coron-diag/src/diag_lab.c:211-214,285-286`: COMPARE0_CLEAR makes latency modulo 1 ms. A 1.2 ms blockage records about 200 µs, loses a tick, and makes the `>=1000` counter effectively unreachable. `base_ms + ticks` at `diag_lab.c:186,314` then ceases to be uptime. Fix: run TIMER4 free-running, advance CC0 by 1000 µs, calculate lateness against the scheduled compare, count skipped periods, and store raw timer/ticker timestamps.

4. blocker — `local/coron-diag/src/diag_lab.c:14-16,223-242`: unrelated 1 kHz sampling cannot guarantee observing the 275–999 µs interval that delayed one BLE prepare.
