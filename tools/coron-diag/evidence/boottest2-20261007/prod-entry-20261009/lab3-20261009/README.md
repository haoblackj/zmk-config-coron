# 記録用ファームウェア v3（本番と同じ割り込み優先度、アサート無効）での計測（2026-10-09 19:21〜19:41）

## 何をしたか
v3（右 md5 `792db3b274aaf545a6b841a5e6c7756b`、左 `577caf51f106777da28196df587d5327`、ELF は `firmware-archive/{R,L}-lab3-<md5>/`、コミット 01fea20）を左右に 1 回ずつ書き、自己試験 3 つ（`A` アサート経路、ブートローダー経由の同じファイルの書き直し、`M` 遅れた準備の経路）が左右とも PASS（`selftest/`）。
刺激は PC との切断とつなぎ直しだけ（`recon-loop.ps1 -StopOnRecord 0`、30 秒待ち）。11 周で止まった（12 周目の `x` の前に読む dump が 30 秒で読み切れなかった。記録 3 件で dump が約 70 KB になるため。以後 60 秒に変更）。

## 結果（`recon/summary.log`、`recon-end-R/decoded.txt`）
11 周のうち 6、7、8 周目で左右間（中央側、ticker id 6）の準備が遅れ、イベントが 1 回ずつ飛んだ（アサート無効なので再起動なし。遅れは 71、38、116 tick = 2.2、1.2、3.5 ms）。PC 側（id 5）の遅れは 0。左は遅れ 0。

3 件とも同じ形:
- PC とつながった直後、PC との接続の最初のイベント（`evcnt=1`。周辺側は中央側の最初の送信を広い窓で待つので、イベントが 4.5〜5.2 ms 続く）の準備が走り、その 2〜5 ms 後に左右間の準備が来て待ち行列に入った（`enqueue conn1` → `prepare conn1 -> queued`）。
- 普段（19:23、19:30 の記録）はこのあと必ず `ticker_start PREEMPT`（横取りタイマーの登録）→ 応答 → 発火 と続くが、3 件ともそれが無い。横取りタイマーが登録されないまま PC のイベントが終わり、そこで左右間の準備が走って遅れと判定された。
- `forced` は 0、監視タイムアウトの残りも正常。中断の判定（`is_abort`）は呼ばれていない（横取りが発火していないので当然）。

つまり `lll.c` の `preempt_ticker_start` が「横取りタイマーは登録済み（またはその登録が未応答）」と判断して早期に返っている（`preempt_start_req != preempt_start_ack || preempt_req != preempt_ack` の枝で、新しい時刻が記憶している時刻より後なら登録しない）。6 周目（起動 716 秒）から 9 周目（944 秒）の間はこの状態が続き、13 周目相当の読み取り（約 1,040 秒）では登録と発火が戻っていた。24 bit の時刻比較は 256 秒で逆転するので、「発火しなかった登録」が一つ残ると最長 256 秒間、横取りが効かない。その登録がいつ、どんな時刻で行われたかは記録の範囲（約 1 秒）の外。v4 は横取り関連だけの長い記録と、記録時点の ticker の一覧を足して、それを取る。
