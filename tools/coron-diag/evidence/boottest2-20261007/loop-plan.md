# 無人ループの計画（レビュー #14 の条件とレビュー #15 の 6 点を取り込んだ版。実装は `calib-loop.ps1` + `calib-trial.ps1`。レビュー待ち。実機では動かしていない）

## 目的
自然発生の起動停止を、計測器 v4（`bt4-R-10080217` / `bt4A-R-10080217`）の事故記録と自動復帰で捕まえる。手動操作、立ち会い、途中の応答は無い。校正の発火（`calib=h/G/S`）は数えない。

## 再現条件（設計 v3、2026-10-08 00:00 の状態コメント）
起動停止 3 件の停止前の稼働時間は 25.6 分、17.8 分、13.1 分（10/07 の 8.1 分は外す）。主試験はこの範囲を含む: 各試行は 13〜26 分の稼働（既定の並び 13, 26, 17, 21, 13 分）の後に 1 回の操作と 1 回の起動を行う。稼働時間はファームの `ZDIAG begin … up_ms=` で測る（`at_us`/`lastfeed_us` は DWT の 32 bit カウンタを 64 で割った値で 67.1 秒で折り返すので時間には使わない）。短周期（10〜30 秒）の繰り返しは別の探索試験とし、0 件でも現場の停止を否定しない。

## 試行の形（`calib-trial.ps1`、司令 `calib-loop.ps1` の期限つき子プロセス）
| 段階 | 操作 | 記録と判定 |
|---|---|---|
| 事前確認 | `calib-run.ps1 -Step pre`（期限 90 秒） | 基準像、最適化像、本番像の 3 ファイルの存在と md5、いまの像からの完全な dump。成立しなければ実機への書き込みを一切始めず、復帰も不要として終わる（レビュー #15 の 2） |
| 基準（試行 0） | 基準像を書いた直後に dump | 既存の全記録を PC へ保存（`calib=` 印のある記録は「校正の名残」、`-` は「自然」と分類）。基準の seq、count、dropped、invalid、reinit を確定。自然の記録が既にあれば停止（起源が曖昧なので事故として扱う）。done=1 を要求 |
| 稼働 | 13〜26 分、app のまま。USB 状態を 10 秒ごとに読む（PnP のみ。コンソールは開かない） | app 以外の状態を最初に見た時点で稼働を打ち切り（残りは消化しない）、90 秒の期限つきで app への復帰を待ち、戻れば記録を読んで保存、戻らなければその状態を保存。どちらも停止し、試験用の `b`/`r`/複写には進まない（レビュー #15 の 4） |
| 稼働終了 | dump | `up_ms`（必須。無ければ FAIL）と `host_conn/host_disc/split_conn/split_disc` を台帳へ。同じ起動の比較: seq、count、dropped、invalid が基準と同じ、reinit の旗が基準と同じ（ファームは起動ごとに 1 回決めて保持する。基準で 1 なら稼働終了でも 1）、`up_ms` が基準より大きい（逆行・停滞は事象）。再現条件: `up_ms(終了) − up_ms(基準)` が [稼働分 × 60 秒 − 2 秒, 稼働分 × 60 秒 + 120 秒]（+120 秒は dump の読み取りと再試行の分）かつ `up_ms(終了) ≥ 稼働分 × 60 秒`。満たさなければ FAIL（操作へ進まない）。丸めた分の値では判定しない（レビュー #15 の 1、3） |
| 操作 | 書き込み群: `b` → 前回と違う像（bt4 ↔ bt4A の交互）を複写 → app 復帰。リセット群: `r` → app 復帰 | `b`/`r` は子 `calib-io.ps1` の関門（直前の dump が完全で `#TRUNC` なし）を通ったときだけ送る。90 秒（`r` は 60 秒）以内に app に戻らなければ「外部応答なし」として、見えた USB 状態を保存して停止（終了コード 11。停止機構は未確定） |
| 起動後 | dump（done=1 になるまで 10 秒おきに最大 6 回） | seq = 前 + 1、count/dropped/invalid 不変、新しい起動では reinit=0、cur の tag = 書いた像、done=1（計測器の RUNNING 到達。コンソールが答えることとは別の観測）。違えば事象: 新規事故記録（count か dropped の増加）、新しい起動での ring 再初期化（計数が失われる）、予想外の起動数、無効記録の増加、RUNNING 未到達。全記録を PC へ保存してから停止（終了コード 10）。dump が取れなければ「観測失敗」として停止（11）。done=0 のまま成功にはしない（レビュー #15 の 3） |

書き込み群と `r` 群は別の実行（`-Mode write` / `-Mode reset`）で、台帳の分母も分かれる。各試行は段階（稼働開始、操作送信、像の複写完了、起動の観測、RUNNING 確認、正常完了）を実績として記録し、分母はそこから数える（「書き込み後の起動」= 像の複写が完了した試行。稼働中に止まった試行は 0 に数える）。予定した像と tag は実績と分けて記録する（`image_planned` / `image_written`、`tag_after_planned` / `tag_after_observed`）。各行は試行番号、操作、起動番号（前後）、操作直前の稼働時間（分）、ring の計数、結果、停止理由を持つ（`ledger.json` / `ledger.csv`。レビュー #15 の 6）。
司令側は子の終了コード 0 を、その試行の結果ファイル（JSON が読める、試行番号が一致、`result=ok`、起動後の seq/count/dropped/invalid/reinit/up_ms/tag/done がそろう、`completed` 段階あり）がそろったときだけ受理する。欠落、壊れた JSON、別試行の結果なら停止して比較対象を空にしたまま続けない。子は結果ファイルの保存に失敗したら失敗として戻る（レビュー #15 の 5）。結果ファイルは、JSON が読めて試行番号が一致し段階の塊を持つ（帰属が確かめられる）ときだけ台帳に採用する。無効・別試行の結果からは成功数も段階も採用しない。その場合は「段階不明」として分母から外し、試行自身のログの刻印（子の `[calib-io] sent 'b'`/`'r'`、複写の `DEVICE-OP copied`）で確認できる操作だけを出所つきで採用する（レビュー #16 の 1）。操作送信の段階は子の `sent` の刻印から決め、交換の成否と独立に結果へ引き継ぐ（送信後に子がタイムアウトしても送信実績は true。子がタイムアウトして刻印が無ければ false にせず「不明」。レビュー #16 の 2）。司令側の例外も失敗として記録し、復帰の方針（実機変更の開始後の通常の失敗は復帰へ、終了未確認なら復帰しない、実機変更前なら復帰不要）は変えない。

## 像の交互書き込みについて
UF2 の内容を 4 KiB ページで比べると bt4 は 93 ページ、bt4A は 104 ページで、同一のページは 0（`python3` で UF2 のブロックを展開して比較）。ブートローダーが実際に消去・書き込みするページ数はこれとは別の量で、計測していない。「全ページ違う」とは主張しない。

## 停止条件と終了
- 事象（上の表）、スクリプトの FAIL、期限超過、終了未確認、周回数の上限（`-Dwells` の個数）、新しい試行を始めない時刻（`-NoNewTrialAfter`。次の試行の稼働 + 操作の待ち約 7 分 + 復帰の予約 `-RestoreReserveMin`（既定 10 分）が収まらなければ始めない）。
- 事象を検出したら、PC への記録保存を終えてから本番復帰する。記録領域は RAM なので、本番像へ戻した後に残ることには依存しない。
- 終了後は結果にかかわらず本番復帰（`calib-flash.ps1 -Expect prod`）。終了未確認（`TIMEOUT-ALIVE`、終了コード 5）のときだけ復帰を試みず、「本番へ戻せなかった」を失敗として記録する。
- 司令側はデバイス、CIM、シリアルに直接触れない。各操作は `Invoke-Child` の期限つき子プロセス（基準像の書き込み 300 秒、試行 = 稼働分 × 60 + 400 秒、復帰 300 秒）で、終了処理は `calib-kill.ps1`（20 秒の期限）。
- 終了コード: 0 = 全試行が事象なしで完了、10 = 事象で停止（記録保存済み）、11 = 外部応答なし／観測失敗で停止、1 = FAIL／期限超過／事前確認の失敗で停止。復帰の失敗・未実施は +2（事前確認で止まったときは復帰不要で +0）。4 = 模擬ファイルの不備。

## 時間の見積もり（既定 5 試行）
稼働 13+26+17+21+13 = 90 分、操作と起動の待ちが各 2〜3 分、基準像の書き込みと本番復帰で約 3 分。合計約 2 時間。`-NoNewTrialAfter` を開始から 2 時間 20 分に置けば、復帰を含めてその時刻までに終わる。

## 報告の分け方
「周回と事故記録の有無（群ごとの分母）」「本番復帰の結果」「未検証事項（ピンリセット、USB を抜いた起動、本番像での再現、自動復帰で救えない停止は観測できないこと）」を分ける。

## 模擬試験（`calib-sim.py`。ループは 24 場面）
模擬の dump はファームの状態遷移に合わせる: 基準像を書いた後の最初の起動（seq 1）は全 dump で reinit=1（ヘッダと cur の両方）、以後の起動は 0。`up_ms` は同じ起動の中で単調に増える。
正常（書き込み群 3 試行）、正常（リセット群 2 試行）、新規事故記録、満杯で dropped 増加、新しい起動での ring 再初期化、同じ起動での reinit 旗の変化、ヘッダと cur の reinit 不一致（dump を拒否）、予想外の起動数、稼働中の離脱と再起動（残りの稼働を消化せず、`b` を送らず、分母 0）、外部応答なし（復帰も失敗）、途中 FAIL（複写エラー。像の複写は分母に入らない）、期限到達（試行を始めない）、終了未確認（復帰を試みない）、本番復帰 FAIL、校正の名残の記録がある基準、基準に自然の記録がある、本番像の欠落と最適化像の md5 不一致（事前確認で止まり、実機変更ゼロ、復帰不要）、起動後 done=0 のまま（成功にしない）、`up_ms` 欠落、稼働時間不足、同じ起動での時間逆行、結果ファイルの欠落、別試行の結果ファイル（無効な結果の段階を集計に入れない）、`b` の送信刻印の後に子がタイムアウト（送信 1、試行 FAIL、復帰）、`r` の同じ場面、送信後のタイムアウトで終了未確認（復帰を試みない）。各場面の終了コード、`results:` 行、集計値を含むログの決め手を機械照合する。
