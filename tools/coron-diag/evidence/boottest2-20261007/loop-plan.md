# 無人ループの計画（レビュー #14 の条件を取り込んだ版。実装は `calib-loop.ps1` + `calib-trial.ps1`。レビュー待ち。実機では動かしていない）

## 目的
自然発生の起動停止を、計測器 v4（`bt4-R-10080217` / `bt4A-R-10080217`）の事故記録と自動復帰で捕まえる。手動操作、立ち会い、途中の応答は無い。校正の発火（`calib=h/G/S`）は数えない。

## 再現条件（設計 v3、2026-10-08 00:00 の状態コメント）
起動停止 3 件の停止前の稼働時間は 25.6 分、17.8 分、13.1 分（10/07 の 8.1 分は外す）。主試験はこの範囲を含む: 各試行は 13〜26 分の稼働（既定の並び 13, 26, 17, 21, 13 分）の後に 1 回の操作と 1 回の起動を行う。稼働時間はファームの `ZDIAG begin … up_ms=` で測る（`at_us`/`lastfeed_us` は DWT の 32 bit カウンタを 64 で割った値で 67.1 秒で折り返すので時間には使わない）。短周期（10〜30 秒）の繰り返しは別の探索試験とし、0 件でも現場の停止を否定しない。

## 試行の形（`calib-trial.ps1`、司令 `calib-loop.ps1` の期限つき子プロセス）
| 段階 | 操作 | 記録と判定 |
|---|---|---|
| 基準（試行 0） | 基準像を書いた直後に dump | 既存の全記録を PC へ保存（`calib=` 印のある記録は「校正の名残」、`-` は「自然」と分類）。基準の seq、count、dropped、invalid、reinit を確定。自然の記録が既にあれば停止（起源が曖昧なので事故として扱う） |
| 稼働 | 13〜26 分、app のまま。USB 状態を 10 秒ごとに読む（PnP のみ。コンソールは開かない） | app 以外の状態を見たら事象として記録 |
| 稼働終了 | dump | `up_ms`（稼働時間）、`host_conn/host_disc/split_conn/split_disc`（接続の計数）を台帳へ。seq、count、dropped、invalid、reinit が基準と同じであること（違えば予想外の再起動／記録の変化として停止） |
| 操作 | 書き込み群: `b` → 前回と違う像（bt4 ↔ bt4A の交互）を複写 → app 復帰。リセット群: `r` → app 復帰 | `b`/`r` は子 `calib-io.ps1` の関門（直前の dump が完全で `#TRUNC` なし）を通ったときだけ送る。90 秒（`r` は 60 秒）以内に app に戻らなければ「外部応答なし」として、見えた USB 状態を保存して停止（終了コード 11。停止機構は未確定） |
| 起動後 | dump | seq = 前 + 1、count/dropped/invalid 不変、reinit=0、cur の tag = 書いた像。違えば事象: 新規事故記録（count か dropped の増加）、ring の再初期化（計数が失われる）、予想外の起動数、無効記録の増加。全記録を PC へ保存してから停止（終了コード 10）。dump が取れなければ「観測失敗」として停止（11） |

書き込み群と `r` 群は別の実行（`-Mode write` / `-Mode reset`）で、台帳の分母も「書き込み後の起動」「ソフトリセット後の起動」に分かれる。各行は試行番号、操作、書いた像、起動番号（前後）、操作直前の稼働時間（分）、ring の計数、結果、停止理由を持つ（`ledger.json` / `ledger.csv`）。

## 像の交互書き込みについて
UF2 の内容を 4 KiB ページで比べると bt4 は 93 ページ、bt4A は 104 ページで、同一のページは 0（`python3` で UF2 のブロックを展開して比較）。ブートローダーが実際に消去・書き込みするページ数はこれとは別の量で、計測していない。「全ページ違う」とは主張しない。

## 停止条件と終了
- 事象（上の表）、スクリプトの FAIL、期限超過、終了未確認、周回数の上限（`-Dwells` の個数）、新しい試行を始めない時刻（`-NoNewTrialAfter`。次の試行の稼働 + 操作の待ち約 7 分 + 復帰の予約 `-RestoreReserveMin`（既定 10 分）が収まらなければ始めない）。
- 事象を検出したら、PC への記録保存を終えてから本番復帰する。記録領域は RAM なので、本番像へ戻した後に残ることには依存しない。
- 終了後は結果にかかわらず本番復帰（`calib-flash.ps1 -Expect prod`）。終了未確認（`TIMEOUT-ALIVE`、終了コード 5）のときだけ復帰を試みず、「本番へ戻せなかった」を失敗として記録する。
- 司令側はデバイス、CIM、シリアルに直接触れない。各操作は `Invoke-Child` の期限つき子プロセス（基準像の書き込み 300 秒、試行 = 稼働分 × 60 + 400 秒、復帰 300 秒）で、終了処理は `calib-kill.ps1`（20 秒の期限）。
- 終了コード: 0 = 全試行が事象なしで完了、10 = 事象で停止（記録保存済み）、11 = 外部応答なし／観測失敗で停止、1 = FAIL／期限超過で停止。復帰の失敗・未実施は +2。4 = 模擬ファイルの不備。

## 時間の見積もり（既定 5 試行）
稼働 13+26+17+21+13 = 90 分、操作と起動の待ちが各 2〜3 分、基準像の書き込みと本番復帰で約 3 分。合計約 2 時間。`-NoNewTrialAfter` を開始から 2 時間 20 分に置けば、復帰を含めてその時刻までに終わる。

## 報告の分け方
「周回と事故記録の有無（群ごとの分母）」「本番復帰の結果」「未検証事項（ピンリセット、USB を抜いた起動、本番像での再現、自動復帰で救えない停止は観測できないこと）」を分ける。

## 模擬試験（`calib-sim.py`。ループは 14 場面）
正常（書き込み群 3 試行）、正常（リセット群 2 試行）、新規事故記録、満杯で dropped 増加、ring 再初期化、予想外の起動数、稼働中の離脱と再起動、外部応答なし（復帰も失敗）、途中 FAIL（複写エラー）、期限到達（試行を始めない）、終了未確認（復帰を試みない）、本番復帰 FAIL、校正の名残の記録がある基準、基準に自然の記録がある。各場面の終了コード、`results:` 行、ログの決め手を機械照合する。
