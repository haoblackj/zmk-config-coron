# Bluetooth の安定化の記録

2026-10-04 から 10-05 にかけて、Bluetooth の不具合を調べて入れた変更と、その根拠の記録です。
ZMK や Zephyr の版を上げるときに確かめることも、ここにまとめます。

## 入れた変更

| 変更 | 場所 | 直したこと |
|---|---|---|
| 設定保存のキャッシュを有効にする | `boards/shields/coron/coron_L.conf`、`coron_R.conf` | 設定の書き込み1回に 0.8〜1.9 秒かかっていた |
| 通知の購読状態を起動時に読む（`CONFIG_BT_SETTINGS_CCC_LAZY_LOADING=n`） | `coron_R.conf` | PC が接続するたびにキー処理が約 0.7 秒止まり、遅れたあと連打になっていた |
| 致命的エラーで止まらず再起動する | `src/fatal_reboot.c` | コントローラの検査に引っかかると、リセットボタンを押すまで固まっていた |
| Zephyr を ZMK 本家の版へ向ける | `config/west.yml` | 右手側が固まる不具合と、接続パラメータ更新で落ちる不具合（どちらも本家が 2026-08-14 に修正） |
| PC と未接続のあいだだけ、左手側との通信をゆっくりにする | `src/split_yield.c` | PC とのつなぎ直しで、確立の失敗が数十回続いていた |

## 確立の失敗が続く件の中身

右手側は、左手側へのセントラルと PC へのペリフェラルを同じ無線で兼ねています。
次の3つがそろうと、PC とのつなぎ直しで確立の失敗（切断理由 `0x3e`）が 30〜45 秒続きます。

1. PC のアダプターが、接続要求の窓の幅を規格の上限（10 ms）、接続間隔をキーボードが申告した範囲の上限（15 ms）で選ぶ。Realtek RTL8922AE で、111 回中 111 回がこの値でした（実測）。
2. Zephyr のコントローラが、確立中のペリフェラル接続の受信を、自分のセントラルのイベントから守らない（ソースの読み。実測ではありません）。
3. ZMK の既定値で、PC との間隔（15 ms）が左手側との間隔（7.5 ms）のちょうど2倍になり、同じ打ち切られ方が6回続く（実測。どちらかを倍数でない値にすると、各 24 回で失敗 0 回）。

`split_yield.c` は、PC とつながっていないあいだだけ左手側との間隔を 28.75 ms に広げ、つながった 150 ms 後に 7.5 ms へ戻します。
打鍵中の左手側の間隔は、入れる前と同じ 7.5 ms です。

| 計測（左手あり、キーボード側から切断） | 失敗が連発した回 |
|---|---|
| 入れる前 | 24 回中 4〜6 回（複数回の計測で同じ傾向） |
| 入れたあと | 切断 94 回、右手側の再起動 10 回で 0 回 |

入れたあとの動きは、切断の約 0.7 秒後に 28.75 ms へ切り替わり、接続の約 0.85 秒後に 7.5 ms へ戻ります。
つながった直後の1秒弱だけ、左手のキーが最大 20 ms ほど遅れることがあります。

退けた案も残しておきます。

- 左手側との間隔を 10 ms や 11.25 ms に広げる。失敗は消えますが、打鍵中の左手の遅延が増えます。
- PC に申告する間隔を 10 ms や 12.5 ms にする。失敗は消えますが、Microsoft の周辺機器向けの指針（接続間隔は 7.5 ms の倍数、キーボードは 15 ms 以上）から外れます。
- コントローラの時間枠の予約を小さくする設定（`CONFIG_BT_CTLR_*_RESERVE_MAX=n`）と、2M PHY を切る設定。どちらも効きませんでした。

## ZMK や Zephyr の版を上げるとき

`split_yield.c` は Zephyr と ZMK の公開 API だけを使っていて、どちらのソースにも手を入れていません。
版を上げても git の衝突は起きませんが、次の点を確かめます。

### ビルドが通らなくなったら

| 使っているもの | 起きうること |
|---|---|
| `bt_conn_get_info()` で読む `info.le.interval` | Zephyr 4.4 で非推奨になりました（`interval_us` へ移行）。警告が出たら、比較をマイクロ秒に直します |
| `bt_conn_le_param_update()`、`bt_conn_foreach()`、`BT_CONN_CB_DEFINE` | 変更の予告は見つかっていません |
| `zmk_ble_active_profile_is_connected()`、`zmk_ble_active_profile_changed` | ZMK はモジュール向けの API を保証していません。名前が変わったら追随します |
| `CONFIG_ZMK_SPLIT_BLE_PREF_INT`、`_LATENCY`、`_TIMEOUT` | 設定名が変わるとビルドが止まります |

### ビルドは通るが、動きを確かめる必要があること

1. **`config/west.yml` の Zephyr に、接続パラメータ更新の修正が入っているか。** `zmkfirmware/zephyr` の `b2aee46d`（上流の `c4171be9` の取り込み）です。入っていない版では、`split_yield.c` が通信条件を切り替えた瞬間に左手側が致命的エラーで落ちます（`lll_peripheral.c` の `LL_ASSERT_OVERHEAD`）。2026-10-05 に、修正の無い `cormoran/zephyr` の `v4.1.0+zmk-fixes+nrf-half-duplex-uart` で実際に起きました。
2. **つなぎ直しで失敗が連発しないか。** `tools/bt-reconnect-check/README.md` の手順で、切断を 24 回以上くり返します。
3. **ZMK が左右間の通信条件を自分で動かすようになっていないか。** そうなっていたら、`split_yield.c` と取り合いになります。ZMK 側に任せて、このファイルを外します。
4. **Zephyr が確立中の接続を優先するようになっていないか。** そうなっていたら、`split_yield.c` は要りません。外して 2 の手順で確かめます。

### 外すとき

`src/split_yield.c` を消し、`CMakeLists.txt` の該当の3行を消します。ほかに依存はありません。

## 分かっていないこと

- 2026-10-05 の朝、右手側が書き込み直後に起動しなかったことが1回あります。書き込まれた中身は正しく、原因は分かっていません。リセットの2度押しで復旧しました。
- 同じ PC で、イヤホンやゲームパッドのつなぎ始めが遅い件は、この調査では説明できていません。キーボードとは別の話です。
- 2 の「コントローラが守らない」は、ソースを読んだ見立てです。Zephyr の開発元には報告していません。
